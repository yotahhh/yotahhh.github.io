# AI Context & Development Guide

Orientation for AI coding assistants and developers working on Yves Spiri's portfolio
site, https://yvesspiri.net/ (repo `yotahhh/yotahhh.github.io`).

## Ground rules
- **Never commit the local-only folders** (all git-ignored, keep them that way):
  `landing_music/` (unreleased audio), `gametrailer/`, `movietrailer/` (video sources),
  `palettes/` (theme reference images), `_REDESIGN/` (the design handoff).
- **Stage files by name, never `git add -A` or `git add .`** An unreleased WAV was once
  published that way (see Open items).
- **Generated files are never hand-edited** (list below); change `src/` or `scripts/`
  and run `npm run build`.
- Copy rules from the client brief are in Content rules below; the build enforces two
  of them (em dashes, contrast).

## Overview
- **Design:** direction H2 "backroom, broken": a slightly broken retro-futurist file
  browser. Striped window title bars, a directory listing as navigation, colour themes
  drawn from reference images, scanlines, a fluorescent wash that drops out once every
  18s and a few small glitches. Type is the Mac OS 9 pairing: Geneva for all text
  (system font on macOS, Verdana elsewhere, nothing hosted) and ChicagoFLF, a
  public-domain Chicago revival self-hosted from `src/assets/fonts/`, only for window
  titles. Chicago everywhere read as too bold.
- **Stack:** plain static HTML/CSS/JS, no framework, no dependencies. A Node ESM script
  (`scripts/build-site.mjs`) renders every page from the content in `src/data/`.
  Media tools used by the helper scripts: `ffmpeg`/`ffprobe` (Homebrew).
- **Deployment:** GitHub Pages serves the repo root of `main` (custom domain in
  `CNAME`, `.nojekyll`). The push is the deploy; check the build with
  `gh api repos/yotahhh/yotahhh.github.io/pages/builds/latest`.

## Project structure
Source:
- `src/data/site.js`: meta, home readme, `landingTrack` (title/artist/note of the home
  player), links, about, mixing & mastering.
- `src/data/projects.js`: `musicProjects`, `filmProjects` (with optional `clips`) and
  `gameProjects`.
- `src/data/themes.js`: `defaultTheme` and the colour themes.
- `src/data/landing-track.json`: generated by `scripts/encode-landing.mjs` (file, key,
  duration, waveform). Committed.
- `src/assets/site.css`: the shared stylesheet. The `:root` tokens are a fallback; the
  themes set the real values. The first part is the reference implementation; inner page
  additions, clips, dock, swatches come after it, then the responsive and
  reduced-motion blocks.
- `src/assets/site.js`: the only script. Sections: landing track + dock, embeds, theme
  swatches, row glitches, film clips, in-place page swaps. Everything bound to page
  content runs from `bindPage()`, which runs on load and after every swap.
- `src/assets/fonts/ChicagoFLF.woff2`.
- `scripts/build-site.mjs`: components (window, directory listing, row, readme, inset,
  image/embed/clip windows, dock, theme switcher) and every page; also the theme CSS,
  the contrast check and real file dates/sizes.
- `scripts/encode-landing.mjs`: prepares the home player's track (see Playback).
- `scripts/dev-server.mjs`: static server that behaves like GitHub Pages (dir/index.html,
  /dir redirects to /dir/, 404.html). It ignores Range requests, so Safari may not play
  video from it; GitHub Pages does serve ranges.

Served as is (committed, not generated): `images/` (covers, photos, game stills),
`clips/` (film loops + posters), `media/` (the scrambled landing track; replaced by
`encode-landing.mjs`).

**Generated, do not hand-edit:** `index.html`, `404.html`, `about/`, `music/`,
`film/`, `games/`, `mixing/`, `contact/`, `assets/`. The build deletes and rewrites those
folders.

## Pages
- `/` home: directory of the site, readme, the landing track player.
- `/about/`, `/mixing/`: folder pages, one listing each, `../` first.
- `/music/<id>/`, `/film/<id>/`, `/games/<id>/`: entry pages (tracks, cover/stills/clips,
  readme, embed). Their listing is the section as a tree (`tree()` in the build): every
  entry, the open one expanded with its files indented under it.
- `/music/`, `/film/`, `/games/`: a copy of the section's first entry page (canonical
  points to the entry), so content is one click from home (`entryPages()`).
- `/contact/`: contact.txt shown in a window (old `/contact.txt` links forward there).
- `/404.html`: "not found". Forwards the old single-page site's `/<id>` release links to
  `/music/<id>/`, and `/contact.txt` to `/contact/`.

## Themes
- Four colour themes, switched by the swatches in every page header: `dumbo` (default),
  `glitter`, `backroom` (the original design) and `glare`. All but backroom are drawn
  from reference images in `palettes/`.
- Each theme in `themes.js` has its full token set; `defaultTheme` picks the default.
  The build appends them to `assets/site.css`: the default as the base `:root`, the
  others as `:root[data-theme="…"]` overrides. Derived colours (shadow, wallpaper
  stripes, scanlines, glitched rows) use `color-mix()`/`var()`, so they follow the theme.
- The choice is stored in `localStorage` (`ys-theme`); an inline script in `<head>`
  applies it before first paint. The favicon uses the default theme's accent.
- The build fails if a text colour is below 4.5:1 on a surface it is used on (the
  `USED` table in `build-site.mjs`). Embeds keep a fixed paper background; Bandcamp
  cannot be recoloured without reloading the player.

## Content rules (from the client brief)
- Text is always dark on a light surface.
- No all caps, no bold: every font is weight 400. Labels lowercase except proper names.
- Dates as `DD.MM.YY`, times 24h. Metric units. The build throws on an em dash in copy.
- No invented content: copy comes from the client or from sources they point to
  (rewritten, not copied).
- Glitches stay subtle. On every page view `site.js` gives one random listing row a
  glitch (`jitter`, `flicker`, `slip`, `chroma`, `stutter`, rotating per view, counter in
  `localStorage` `ys-glitch`). The home and music listings also have one cut-off date.
  No "unreadable" note, no error dialog, no static strip (all removed on request).
- Respect `prefers-reduced-motion` (animations stop; clips do not autoplay).

## Dates and sizes
The "modified" column is the last git commit touching the file behind a row (its image,
clip or the data file), in Europe/Zurich time, falling back to the file's mtime. Sizes
are real byte sizes. So a rebuild right after a commit can change dates in the generated
pages; that is expected, commit them with the next change.

## Workflows
- **Preview:** `npm run dev` (builds, then serves http://127.0.0.1:5173; also the
  `portfolio` entry in `.claude/launch.json`).
- **Publish:** `npm run build`, stage the changed source and generated files by name,
  commit, push `main`.
- **Add a release:** cover in `images/`, entry in `musicProjects` (`id`, `title`,
  `description`, `image`, optional `extendedDescription`, `tracks` as `1. Name 04:23`
  lines, `credits`, `bandcampLink`, `embedUrl` or `soundcloudEmbed`). Order is roughly
  newest first.
- **Add a film:** entry in `filmProjects` (`id`, `title`, `description`, optional
  `image` poster, `status`, `embedUrl` for Vimeo, `clips`).
- **Add film clips:** renders go in `movietrailer/`. The Terminarch render has burned-in
  timecode top-left and 20px black bars, so it is cropped below them:
  `ffmpeg -ss <start> -i <render> -t <seconds> -vf "crop=1600:900:160:160,scale=960:540:flags=lanczos,format=yuv420p" -c:v libx264 -preset slow -crf 25 -movflags +faststart -af "afade=t=in:d=0.15,afade=t=out:st=<seconds-0.15>:d=0.15" -c:a aac -b:a 128k clips/<film>_<name>.mp4`,
  then the first frame as `clips/<film>_<name>.jpg` (poster), then an entry in the
  film's `clips` (`name`, `file`, `from`, `to`, `alt`). Cut on shot changes
  (`select='gt(scene\,0.2)',showinfo` lists them) and avoid animatic shots. A cleaner
  render without timecode would need no crop.
- **Add a game:** stills in `images/` (from a trailer in `gametrailer/`:
  `ffmpeg -ss <seconds> -i <trailer> -frames:v 1 -vf scale=1600:-2 -q:v 4 images/<name>.jpg`),
  then an entry in `gameProjects` (`id`, `title`, `description`, `credits`, `stills`,
  `link`).
- **Add a theme:** reference image in `palettes/`, extract dominant and saturated colours
  (Pillow median-cut was used), add a full token set to `themes.js`; the build checks
  contrast.
- **Replace the landing track:** `npm run encode:landing -- landing_music/<file>.wav`,
  update `landingTrack` in `site.js`, build, commit `media/`, `src/data/landing-track.json`
  and the generated files.

## Playback
- **Home page player:** one unreleased track. `encode-landing.mjs` encodes the WAV to
  AAC 128k in an .m4a (~4.3 MB), XOR-scrambles it with a random key into
  `media/<hash>.bin` and writes `landing-track.json`. `site.js` fetches it on first
  hover/focus/click of play, unscrambles it and plays a blob URL. This only stops casual
  downloading; the key is in the page.
- **Dock and background play:** every page carries a hidden `.dock` (the track's data
  plus a play/pause button), pinned bottom-right once the track starts. From then on,
  `site.js` swaps `main.page` in place for internal links ending in `/` (fetch +
  pushState, popstate on Back), so audio keeps playing; other files (images) open in a
  new tab. Before anything plays, links navigate normally. Media Session gives
  lock-screen and media-key control.
- **Embeds:** Bandcamp/SoundCloud (recoloured in `bandcamp()`/`soundcloud()`) and one
  Vimeo. Bandcamp has no player API, so a click into an embed (window blur with an
  iframe focused) counts as it starting; reloading the iframe is the only way to stop
  it. A started embed survives page swaps: its page is kept as `main.ghost` (fixed,
  clipped, invisible) and only its `.inset` shows, pinned to the corner as `.docked`
  with a close button. An iframe cannot be moved without reloading, hence the ghost.
- **Film clips:** loop muted while on screen (IntersectionObserver), like GIFs. The
  sound button unmutes one at a time. Clips stop when you leave their page.
- **Only one thing makes sound:** landing track, embed and clip sound take turns;
  starting one pauses, stops or mutes the others (`stopEmbed()`, `muteClips()`,
  `audio.pause()`).
